AI Plugin Security Checklist

Before you install any AI agent plugin or MCP server, run through this list.

🔒 Manifest & Identity

Plugin has a valid plugin.json with all required fields
ID uses kebab-case (e.g., my-safe-plugin)
Version follows semver (e.g., 1.2.3)
Author/organization is identifiable and has a GitHub presence
Repository URL is valid and accessible

🛡️ Security Files

SECURITY.md exists with supported versions and vulnerability reporting process
LICENSE exists (Apache 2.0, MIT, or similar open-source license)
No hardcoded secrets, API keys, tokens, or passwords in the codebase
No private keys or certificate files committed

⚠️ Dangerous Code Patterns

No eval() or new Function() calls
No shell command execution (child_process, exec, system)
No rm -rf, sudo, or curl | sh patterns
MCP remotes use HTTPS, not HTTP
No overly broad file system access

🔧 CI/CD & Supply Chain

GitHub Actions are pinned to commit hashes (not @v1)
No permissions: write-all in CI workflows
Dependabot is configured for automated updates
Package lockfiles exist (package-lock.json, yarn.lock, poetry.lock)

📋 Documentation

README.md explains what the plugin does and how to use it
SKILL.md has proper frontmatter (title, description, tags)
Skills directory is present and well-organized
.codexignore file exists to exclude sensitive files from AI context

✅ Automated Verification

Run the HOL Guard scanner to verify everything:

plugin-scanner scan /path/to/plugin --format text

Passing criteria:

  • Score ≥ 80/130
  • No critical or high severity findings
